### `01 / OVERVIEW`

</div>

**Skills Lab** is a personal software engineering laboratory.

A single environment for:

`LEARNING` → `BUILDING` → `EXPERIMENTING` → `TESTING` → `SHIPPING` → `IMPROVING`

This repository brings together programming, web, mobile, quality, cloud, technical research, and product development.

The objective is simple:

> **Turn technical knowledge into demonstrable engineering capability.**

### `DESIGN PRINCIPLE`

The root stays intentionally small.

```text
HIGH-LEVEL
    ↓
CAPABILITY
    ↓
DOMAIN
    ↓
IMPLEMENTATION
    ↓
SYSTEM
```

No unnecessary:

`day01/` · `day02/` · `practice/` · `solutions/` · `random/`

The structure represents **engineering capabilities**, not course progression.

### `07 / EXPERIMENTS`

</div>

> **This is a lab. Experiments are first-class citizens.**

Questions worth investigating:

```text
WHY?
HOW?
WHAT IF?
WHAT BREAKS?
WHAT SCALES?
WHAT FAILS?
WHAT COSTS MORE?
WHAT PERFORMS BETTER?
WHAT IS SIMPLER?
```

### Experiment model

<p align="center">

`QUESTION`
→
`HYPOTHESIS`
→
`IMPLEMENT`
→
`MEASURE`
→
`RESULT`
→
`LEARNING`

</p>

**Curiosity → Evidence.**

      ↓

<div align="center">

### `09 / DECISIONS`

</div>

Technical decisions should be explainable.

```text
CONTEXT
  ↓
PROBLEM
  ↓
CONSTRAINTS
  ↓
OPTIONS
  ↓
EVALUATION
  ↓
DECISION
  ↓
TRADE-OFFS
  ↓
CONSEQUENCES
```

A strong decision explains:

* what was needed
* what alternatives existed
* why one option won
* what was sacrificed
* what changed afterward
