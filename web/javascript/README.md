## ◈ Overview

**JavaScript Engineering Lab** is the dedicated JavaScript learning workspace within [`skills-lab`](../../README.md).

It documents my progression from language fundamentals to modern JavaScript concepts, browser APIs, asynchronous programming, and project development.

The objective is to build a strong understanding of the language, write readable and maintainable code, and establish the JavaScript foundation required for frontend engineering and React development.

### Core objectives

* Build a clear understanding of JavaScript syntax, variables, and data types.
* Develop proficiency with functions, scope, closures, arrays, and objects.
* Understand prototypes, classes, and modern ECMAScript features.
* Work confidently with the DOM, browser events, and web storage.
* Master asynchronous JavaScript, promises, `async`/`await`, and API integration.
* Apply modules, npm, Node.js, and modern development tooling.
* Translate concepts into practical implementations and portfolio-ready projects.

## ◈ Engineering Principles

### 01 — Understand Before Implementing

Learn the underlying behavior of a feature before relying on it in an application.

### 02 — Learn by Writing Code

Type examples, experiment with values, inspect outputs, and reproduce concepts without blindly copying solutions.

### 03 — Prefer Readability

Use descriptive names, consistent formatting, small focused functions, and clear file organization.

### 04 — Debug Systematically

Read error messages, inspect runtime behavior, use browser DevTools, and verify assumptions.

### 05 — Build Incrementally

Connect individual concepts to practical applications as the foundational knowledge develops.

### 06 — Track Work with Git

Use meaningful commits to document changes and maintain a clear development history.

## ◈ Code Organization

Each topic should remain focused, discoverable, and easy to review.

```text
javascript/
├── README.md
├── 01-fundamentals/
│   ├── README.md
│   ├── 01-setup/
│   │   ├── index.html
│   │   └── hello-world.js
│   ├── 02-variables/
│   │   ├── variables.js
│   │   └── variable-naming.js
│   └── 03-data-types/
│       ├── primitive-types.js
│       ├── reference-types.js
│       └── typeof-operator.js
├── 02-control-flow/
├── 03-functions/
├── 04-arrays/
├── 05-objects/
├── 06-classes-and-built-ins/
├── 07-dom/
├── 08-events-and-storage/
├── 09-asynchronous-javascript/
├── 10-fetch-and-rest-apis/
├── 11-modules-and-tooling/
└── 12-capstone-projects/
```

**Organization standards**

* Keep filenames descriptive and topic-specific.
* Add a `README.md` when a topic needs explanations or execution instructions.
* Separate browser examples from standalone Node.js examples when their environments differ.
* Avoid committing generated dependencies, credentials, or environment-specific secrets.
* Keep project-level applications distinct from isolated language demonstrations.
